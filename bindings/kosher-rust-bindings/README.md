# kosher-rust-bindings

kosher-rust for other languages: a C ABI over the whole library, with bindings for Node/TypeScript,
Python, Swift, Kotlin, Dart, .NET, Go, Ruby, C, C++ and WebAssembly generated by
[WeaveFFI](https://weaveffi.com).

Not published yet; the API may change.

## What's exported

One root namespace, `kosher`, with four modules:

| Module | Contents |
|---|---|
| `calendar` | `HebrewDate` (holidays, parsha, molad, ...), `year_info`, holiday/parsha/month names |
| `zmanim` | `Zmanim`, the `Zman` enum (all 167 KosherJava times), `Config`, zman names and descriptions |
| `limudim` | Daf Yomi (Bavli and Yerushalmi), Daf Hashavua, Amud Yomi, Mishna Yomis, Tehillim, Pirkei Avos |
| `myzmanim` | `MyZmanim` and the `MyZman` enum: the MyZmanim website's times |

Conventions:

- **Instants** are milliseconds since the Unix epoch (an `i64`: a `bigint` in JavaScript);
  durations are milliseconds.
- **Gregorian dates** are `GregorianDate { year, month, day }` records.
- **Time zones** come from you, as a `TimeZoneOffset` callback that returns the UTC offset in
  seconds at a Unix time. Nothing else is needed, and no time zone database is bundled. Without
  one, everything works except the Kiddush Levana times and places more than 150° from Greenwich.
- **Errors** are typed: `InvalidLatitudeError`, `AllNightError`, `TimeZoneCallbackFailedError`,
  and so on, under `KosherError`.

## Generate

```bash
cargo install weaveffi-cli --version 0.25.0 --locked
cd bindings/kosher-rust-bindings
weaveffi generate          # builds the library, rewrites generated/<language>/
```

### Node

```bash
cd generated/node
KOSHER_RUST_BINDINGS_LIBRARY=../../../../target/debug npm install
```

```js
import { kosher } from 'kosher-rust-bindings';
const { zmanim, calendar, limudim } = kosher;

const newYork = { offsetSeconds: (unixSeconds) => /* seconds east of UTC at that instant */ -4 * 3600 };
const day = new zmanim.Zmanim(
  kosher.seaLevelLocation(40.09, -74.22),
  { year: 2024, month: 4, day: 23 },
  zmanim.defaultConfig(),
  newYork,
);
new Date(Number(day.get(zmanim.Zman.SofZmanShmaGra)));

const date = calendar.HebrewDate.fromGregorian({ year: 2024, month: 4, day: 23 });
date.holidays(calendar.Region.Diaspora); // [{ tag: 'Pesach' }]
limudim.dafYomiBavli(date).display;     // 'Bava Metzia 55'
```

`tests/node/smoke.test.mjs` has a complete `Intl`-backed time zone.

### Python

```bash
KOSHER_RUST_BINDINGS_LIBRARY=../../target/debug/libkosher_rust_bindings.so \
    PYTHONPATH=generated/python python examples/smoke.py
```

## Development

- `src/api.rs` declares everything exported; WeaveFFI reads it to generate the bindings, so it has
  to be written out in full, inline. `src/convert/` converts to and from kosher-rust's types.
- The `Zman` and `MyZman` enums are generated from kosher-rust. After a zman is added, run
  `UPDATE_GENERATED=1 cargo test -p kosher-rust-bindings codegen`; until then the conversions
  don't compile and the drift test fails.
- `cargo test -p kosher-rust-bindings` checks the bindings against kosher-rust. Among other things,
  every zman over a year at six places, with all three solar algorithms, through a callback time
  zone, must equal kosher-rust's with jiff's time zone.
- `generated/` is committed. After changing the API (or upgrading WeaveFFI or kosher-rust), run
  `weaveffi generate` here and commit the result: CI regenerates every language and fails if
  anything in `generated/` changed, appeared or disappeared.
- CI (the `bindings` job) runs those tests, checks `generated/` is up to date, and runs the Node
  tests against it.
